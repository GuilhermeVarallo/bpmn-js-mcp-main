Início

O que é o MCP de BPMN

O MCP (Model Context Protocol) é a forma de plugar ferramentas novas no Claude. Com o MCP de BPMN, ele deixa de apenas descrever o processo em texto e passa a criar, alterar, validar e exportar diagramas de verdade.

O servidor é o bpmn-js-mcp, de código aberto (licença MIT). Por baixo, ele usa o bpmn-js, o mesmo motor do bpmn.io e do Camunda Modeler — então tudo o que ele gera abre em qualquer ferramenta compatível com BPMN 2.0.

Sem cadastro, sem assinatura, e os seus processos não saem do seu computador.

Etapa 1

Todas as ferramentas disponíveis

São 20. Não precisa decorar: o Claude escolhe a certa conforme o que você pede. Abra cada grupo para ver para que serve cada uma.

Diagramas (5)
  • create_bpmn_diagram Começa um diagrama novo, copia um existente ou importa um .bpmn
  • list_bpmn_diagrams Mostra os diagramas abertos e compara duas versões
  • delete_bpmn_diagram Tira um diagrama da memória
  • bpmn_history Desfaz e refaz mudanças
  • batch_bpmn_operations Aplica várias mudanças numa chamada só
Elementos e conexões (6)
  • add_bpmn_elements Inclui tarefas, eventos e gateways, já ligados em sequência se quiser
  • connect_bpmn_elements Liga elementos com fluxos, com rótulos como “Sim” e “Não”
  • delete_bpmn_element Remove elementos ou ligações
  • move_bpmn_element Move, redimensiona ou troca um elemento de raia
  • set_bpmn_element_properties Ajusta propriedades, timers, mensagens, erros e extensões Camunda
  • manage_bpmn_root_elements Cria mensagens e sinais compartilhados
Pools e raias (3)
  • create_bpmn_participant Cria pools, inclusive em volta de um processo pronto
  • create_bpmn_lanes Cria raias e distribui as etapas entre elas
  • analyze_bpmn_lanes Avalia a divisão em raias e sugere melhorias
Layout (2)
  • layout_bpmn_diagram Organiza tudo automaticamente, da esquerda para a direita
  • align_bpmn_elements Alinha e espaça os elementos escolhidos
Revisão e exportação (4)
  • validate_bpmn_diagram Confere o diagrama com dezenas de regras de boas práticas
  • export_bpmn Gera BPMN 2.0, SVG, PNG, GIF/MP4 animado ou HTML interativo
  • list_bpmn_elements Lista os elementos com tipo, posição e ligações
  • list_bpmn_process_variables Mostra as variáveis usadas no processo

Etapa 3

Instalação em 1 prompt

Copie o prompt abaixo e cole no Claude Code ou no Claude Desktop:

Prompt de instalação 
Claude, instale para mim o servidor MCP de BPMN que está neste repositório:
https://github.com/GuilhermeVarallo/bpmn-js-mcp-main

1. Confira se o meu computador tem Node.js 22 ou mais novo e o Git. O que estiver faltando, me ajude a instalar.
2. Baixe o repositório com git clone para uma pasta que não vá mudar de lugar (sugestão: Documentos/MCP BPMN). Dentro dela, rode "npm ci" e verifique se o arquivo dist/index.js foi criado.
3. Cadastre o servidor com o nome "bpmn":
   - no Claude Code: claude mcp add --scope user bpmn -- node "<pasta>/dist/index.js"
   - no Claude Desktop: inclua o servidor no arquivo claude_desktop_config.json
4. Faça um teste: um diagrama com início, uma tarefa e fim; valide e exporte em PNG.

Quando precisar que eu faça alguma coisa, me explique passo a passo. No final, me mostre como usar.

Pronto. O Claude baixa o projeto, instala o que for preciso, cadastra o servidor e faz o teste. No fim ele vai pedir para você reiniciar o aplicativo — quando o conector bpmn aparecer ativo, está tudo funcionando.

Quer fazer você mesmo ou entender o que o Claude fez?

Instalação manual, passo a passo

No terminal, na pasta onde você quer deixar o MCP:

Terminal 
git clone https://github.com/GuilhermeVarallo/bpmn-js-mcp-main.git "MCP BPMN"
cd "MCP BPMN"
npm ci

O npm ci instala as dependências e já gera o servidor em dist/index.js. Falta só cadastrá-lo no Claude (itens abaixo).

Cadastrar no Claude Code

Troque o caminho pelo da pasta onde você clonou:

Terminal 
claude mcp add --scope user bpmn -- node "C:/Users/<voce>/Documents/MCP BPMN/dist/index.js"

O --scope user deixa o servidor disponível em qualquer projeto. Confira com claude mcp list.

Cadastrar no Claude Desktop

No Claude Desktop, abra Configurações → Desenvolvedor → Editar configuração (o arquivo claude_desktop_config.json) e inclua:

claude_desktop_config.json 
{
  "mcpServers": {
    "bpmn": {
      "command": "node",
      "args": ["C:\\Users\\<voce>\\Documents\\MCP BPMN\\dist\\index.js"]
    }
  }
}

No Windows, cada barra do caminho vai dobrada (\\). No Mac, use o caminho normal, por exemplo /Users/<voce>/Documents/MCP BPMN/dist/index.js. Depois feche o Claude Desktop por completo e abra de novo.

Deu erro? Os mais comuns
  • “node” ou “git” não é reconhecido. O programa não está instalado ou o terminal foi aberto antes da instalação. Instale e abra um terminal novo.
  • O npm ci falhou. Confira a versão com node -v (precisa ser 22 ou mais nova), apague a pasta node_modules e rode de novo.
  • O conector bpmn não aparece. Feche o Claude por completo (inclusive da bandeja do sistema) e abra de novo. Se continuar, confira se o caminho do dist/index.js está certo e se o arquivo existe.
Não pode instalar nada? Use o servidor na nuvem

Há também uma versão deste servidor hospedada na internet, para quem não pode instalar programas. Ela pede um token de acesso (fornecido por quem administra o serviço) e só funciona no Claude Code e no VS Code:

Terminal 
claude mcp add --transport http bpmn https://<este-site>/mcp --header "Authorization: Bearer <seu-token>"

Na nuvem, os diagramas ficam guardados por 7 dias e o resultado volta na conversa (XML, SVG ou PNG), sem gravar arquivos no seu computador.

Etapa 4

Os 7 superpoderes

Agora vem a parte boa. Cada cartão traz o que ele faz, um prompt pronto para copiar e o resultado que você pode esperar.

01

Desenhar um processo do zero

Conte o processo do jeito que contaria a um colega. O Claude monta o diagrama.

Prompt 
Crie um diagrama BPMN da contratação de fornecedor: compras recebe a solicitação, pede três orçamentos e escolhe o melhor; se o valor passar de R$ 10 mil, a diretoria precisa aprovar antes do contrato. Exporte em PNG e em .bpmn.

O que esperar: início, tarefas, um gateway para a decisão do valor com os dois caminhos rotulados e o fim — tudo organizado da esquerda para a direita e salvo como imagem e como BPMN 2.0.

02

Transformar um documento em fluxo

Tem um POP, um procedimento em Word ou a ata de uma reunião? Cole o texto.

Prompt 
Abaixo está o procedimento de [admissão de funcionários]. Converta em um fluxo BPMN fiel ao texto, apontando as decisões e quem executa cada etapa. No final, liste o que o documento deixa ambíguo.

[cole o texto aqui]

O que esperar: o texto vira desenho, com as decisões e os responsáveis à mostra. De quebra, aparecem as lacunas que o documento não explica.

03

Separar responsabilidades em raias

Mostre quem faz o quê — ótimo para alinhar áreas e apresentar ao cliente.

Prompt 
Ponha esse processo em um pool "Empresa" com as raias Solicitante, Compras e Diretoria. Organize o layout primeiro e só depois coloque cada etapa na raia de quem a executa.

O que esperar: o mesmo fluxo em faixas por responsável, com as passagens de uma área para outra visíveis. O Claude também sabe avaliar a divisão e sugerir outra melhor.

04

Revisar e encontrar erros

O MCP traz um revisor com dezenas de regras de boas práticas de BPMN.

Prompt 
Valide o diagrama e me explique, sem jargão, cada erro e cada aviso. Corrija os erros e diga quais avisos eu posso deixar de lado.

O que esperar: problemas como caminho sem fim, decisão sem fechamento, loop sem limite ou fluxos que se juntam sem gateway. Com erro grave, o próprio revisor segura a exportação até a correção.

05

Editar diagramas que você já tem

Abre arquivos BPMN 2.0 de outras ferramentas, como o Camunda Modeler e o bpmn.io.

Prompt 
Abra o arquivo C:\Processos\compras.bpmn, inclua uma etapa "Conferir nota fiscal" logo depois do recebimento do material e salve como uma nova versão.

O que esperar: o diagrama aberto, alterado e salvo, sem você abrir editor nenhum. Qualquer mudança pode ser desfeita.

06

Exportar para apresentar

O mesmo processo em vários formatos: proposta, documentação ou post.

Prompt 
Exporte o processo em PNG com fundo branco para a apresentação, em SVG para a documentação e em GIF animado mostrando o fluxo acontecendo.

O que esperar: PNG em alta resolução, SVG vetorial, BPMN 2.0, HTML interativo ou animação (GIF, MP4, WebP). A animação leva alguns segundos a mais para ficar pronta.

07

Preparar para automação

Para rodar o processo de verdade num motor de workflow, como Camunda 7 ou Operaton.

Prompt 
Deixe esse processo executável no Camunda 7: responsáveis e formulários nas tarefas de usuário, condições nos gateways e um prazo de 2 dias na aprovação da diretoria.

O que esperar: um processo executável, com variáveis, formulários e responsáveis definidos, pronto para importar no motor.

Na prática

Boas práticas e limites

O que aprendemos usando o MCP em processos reais.

  1. 1
    Peça o arquivo .bpmn no final.

    O diagrama vive na memória enquanto o Claude está aberto. Se fechar sem exportar, ele se perde.

  2. 2
    Com raias, primeiro o layout.

    Se o layout automático rodar depois de distribuir as raias, as etapas podem voltar todas para uma raia só. Organize antes e distribua depois.

  3. 3
    Nem todo aviso é defeito.

    As regras de nome de tarefa foram feitas para o inglês e reclamam de nomes em português. Avisos de responsáveis e variáveis só importam se o processo for rodar no Camunda.

  4. 4
    A regra de negócio é com você.

    O Claude cuida da notação. Se o desenho corresponde ao que acontece de fato na empresa, quem confirma é você — e quem vive o processo.

Exemplo real

Do pedido ao diagrama

Este diagrama foi gerado pelo MCP a partir de uma frase. Nenhuma caixa foi arrastada à mão.

O pedido “Modele o reembolso de despesas: o colaborador envia o comprovante, o gestor avalia e, se aprovar, o financeiro paga. Use raias para cada área.”

E agora?

O seu Claude acabou de ganhar 20 ferramentas de modelagem de processos. Ele desenha, revisa e exporta em minutos o que levaria horas de arrastar caixinhas.

A ferramenta, porém, é só metade do caminho. A outra metade é saber o que vale mapear: onde o processo trava, o que compensa automatizar e como ele deveria funcionar.
