Guia prático · sem instalar nada

Claude + BPMN: modele processos em uma conversa

Conecte o seu Claude a este servidor e ele passa a criar, revisar e exportar diagramas BPMN 2.0 de verdade — com o mesmo motor do bpmn.io e do Camunda Modeler. Você descreve, ele desenha.

Conectar em 1 minuto ↓ Ver as ferramentas

O que o seu Claude passa a fazer

  • Desenhar um processo a partir de uma descrição em texto livre
  • Transformar um procedimento ou POP em fluxo BPMN
  • Organizar responsabilidades em pools e raias
  • Revisar o diagrama contra dezenas de regras de boas práticas
  • Editar um .bpmn que você já tem
  • Entregar o resultado em PNG, SVG ou XML (abre no Camunda Modeler e no bpmn.io)
  • Preparar o processo para execução no Camunda 7 / Operaton

Como funciona

1

Você conversa

Pede em português, como pediria a um analista de processos.

2

O Claude usa as ferramentas

Ele chama este servidor (protocolo MCP) para criar elementos, conectar, organizar o layout e validar.

3

Você recebe o diagrama

Em imagem para apresentar ou em XML BPMN 2.0 para abrir em qualquer modelador.

O servidor fica na nuvem: não há nada para instalar além do próprio Claude. O acesso é protegido por token — peça o seu a quem administra este serviço.

Passo 1

Conectar o Claude

Você vai precisar de duas coisas:

  • O endereço do servidor: https://<este-site>/mcp
  • O seu token de acesso (64 letras e números).

Claude Code (terminal)

Cole no terminal, trocando <seu-token> pelo seu token:

claude mcp add --transport http bpmn https://<este-site>/mcp --header "Authorization: Bearer <seu-token>"

VS Code (GitHub Copilot / agentes)

Crie o arquivo .vscode/mcp.json no seu projeto. O VS Code pergunta o token na primeira vez e guarda com segurança: 

{
  "servers": {
    "bpmn": {
      "type": "http",
      "url": "https://<este-site>/mcp",
      "headers": { "Authorization": "Bearer ${input:bpmn-token}" }
    }
  },
  "inputs": [
    { "id": "bpmn-token", "type": "promptString", "password": true, "description": "Token do BPMN MCP" }
  ]
}
E o Claude Desktop ou o claude.ai?

Os conectores remotos adicionados pela interface do Claude Desktop e do claude.ai exigem login OAuth, e este servidor usa token. Por enquanto, use o Claude Code ou o VS Code.

Passo 2

Testar a conexão

Abra uma conversa nova e cole:

Use as ferramentas BPMN para criar um processo simples: "Pedido recebido" → "Analisar pedido" → "Pedido concluído". Organize o layout e me mostre em PNG.

Se aparecer a imagem do diagrama, está tudo certo.

Passo 3

Prompts prontos para o dia a dia

Copie, troque o que está entre colchetes e envie.

1 Desenhar um processo do zero

Modele em BPMN o processo de [reembolso de despesas]: [o colaborador envia o comprovante, o gestor aprova ou recusa; se aprovado, o financeiro paga em até 5 dias]. Nomeie as tarefas com verbo + objeto, use gateway para cada decisão, organize o layout, valide e me mostre em PNG.

2 Transformar um documento em fluxo

Abaixo está o procedimento [nome do POP]. Transforme em um diagrama BPMN fiel ao texto, sem inventar etapas; liste no final o que ficou ambíguo no documento.

[cole aqui o texto do procedimento]

3 Separar responsabilidades em raias

Coloque o processo em um pool "[nome da organização]" com raias para [Solicitante, Gestor, Financeiro]. Distribua cada tarefa na raia de quem a executa e reorganize o layout.

4 Revisar e encontrar erros

Valide o diagrama e explique em português cada problema encontrado, do mais grave ao mais leve. Corrija os erros e me mostre o antes e o depois.

5 Editar um diagrama que você já tem

Leia o arquivo [processo.bpmn], carregue o XML dele no servidor BPMN e [inclua uma etapa de aprovação da diretoria antes do pagamento]. Ao final, exporte o XML e salve por cima do arquivo.

O servidor não acessa os seus arquivos: quem lê e salva é o Claude, na sua máquina. Por isso o pedido fala em “carregar o XML”.

6 Exportar para apresentar

Exporte o diagrama em PNG para eu colar na apresentação e em XML para abrir no Camunda Modeler.

7 Preparar para automação

Torne o processo executável no Camunda 7: defina responsáveis nas tarefas de usuário, formulários com os campos [valor, justificativa], condições nos gateways e um timer de [2 dias] na aprovação. Liste as variáveis do processo no final.

Todas as ferramentas (20)

Você não precisa chamá-las pelo nome: o Claude escolhe sozinho. Servem de referência.

Diagramas 5
create_bpmn_diagram
Cria um diagrama em branco, copia outro ou importa um XML BPMN.
list_bpmn_diagrams
Lista os seus diagramas ou resume um deles; também compara dois.
delete_bpmn_diagram
Apaga um diagrama.
bpmn_history
Desfaz ou refaz alterações.
batch_bpmn_operations
Executa várias operações de uma vez.
Elementos e conexões 6
add_bpmn_elements
Adiciona tarefas, eventos e gateways, já encadeados se quiser.
connect_bpmn_elements
Liga elementos com fluxos (com rótulo, como “Sim” e “Não”).
delete_bpmn_element
Remove elementos ou conexões.
move_bpmn_element
Move, redimensiona ou muda um elemento de raia.
list_bpmn_elements
Lista os elementos com tipo, nome, posição e ligações.
set_bpmn_element_properties
Define propriedades, eventos (timer, mensagem, erro) e extensões Camunda.
Pools e raias 3
create_bpmn_participant
Cria pools, inclusive envolvendo um processo existente.
create_bpmn_lanes
Cria raias e distribui as tarefas entre elas.
analyze_bpmn_lanes
Sugere e avalia a organização das raias.
Layout 2
layout_bpmn_diagram
Organiza o diagrama automaticamente, da esquerda para a direita.
align_bpmn_elements
Alinha e distribui elementos selecionados.
Validação, exportação e automação 4
validate_bpmn_diagram
Confere o diagrama com as regras do bpmnlint e do Camunda 7.
export_bpmn
Entrega o diagrama em XML, SVG ou PNG.
manage_bpmn_root_elements
Cria mensagens e sinais compartilhados.
list_bpmn_process_variables
Lista as variáveis usadas no processo.

Deu erro?

“Unauthorized” (401)

O token não chegou ou está errado. Confira se não ficou espaço ou quebra de linha a mais ao colar, e se o cabeçalho é exatamente Authorization: Bearer <token>. Abrir /mcp direto no navegador sempre dá 401: ele não envia o token.

“Not found” ou a página pede login da Vercel

Use o endereço de produção terminado em /mcp. Os endereços de prévia (…-git-…vercel.app) ficam atrás do login da Vercel, que o Claude não consegue fazer.

“Diagram not found”

Os diagramas ficam guardados por 7 dias sem uso, até 20 por token. Passado isso, peça ao Claude para recriar a partir do XML que você exportou.

Erro 500 em tudo

O servidor está sem configuração (token ou banco). Avise quem administra o serviço: o log da função informa o que falta.

Boas práticas e limites

  • Peça sempre o XML ao final: é o seu arquivo de verdade.
  • Diagramas ficam 7 dias sem uso e no máximo 20 por token.
  • Quem usa o mesmo token vê os mesmos diagramas — cada pessoa ou equipe deve ter o seu.
  • Exporta XML, SVG e PNG. Animações (GIF, MP4) e HTML interativo ficam só na versão local.
  • Comece pelo caminho feliz e acrescente exceções depois — o resultado sai mais limpo.
